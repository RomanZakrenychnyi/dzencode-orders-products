# Запуск приложения в Docker

Нужны Docker Desktop (Linux containers) и Git. Node.js на компьютере для запуска контейнеров не требуется.

## Первый запуск

Из корня репозитория скопируйте `.env.example` в `.env`:

```bash
cp .env.example .env
```

Если `.env` уже существует, не перезаписывайте его: сохраните текущие пароли MySQL и добавьте недостающие поля из примера. Сгенерируйте секрет (вывод предназначен только для локального `.env`):

```bash
docker run --rm node:24-bookworm-slim node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Скопируйте результат в `JWT_SECRET=`. Файл `.env` исключён из Git и Docker build context. Без секрета длиной минимум 32 символа API не запустится.

Остановите локальные `npm run dev` и `npm run dev:api`, чтобы освободить порты 3000 и 4000. Затем:

```bash
docker compose up --build -d --wait
docker compose ps
```

Три сервиса должны получить статус `healthy`:

| Сервис | Назначение | Адрес |
| --- | --- | --- |
| web | Next.js production, SSR | http://localhost:3000 |
| api | Express, JWT, Socket.io | http://localhost:4000/health/db |
| db | MySQL 8.4 | 127.0.0.1:3307 |

Вход: `demo@example.com` / `DemoPass123!`, если значения не изменены. API применяет миграцию авторизации и создаёт демо-пользователя при старте. Повторный запуск не меняет пароль существующего аккаунта. Схема и демонстрационные товары загружаются только при первом запуске с пустым томом.

## Данные и окружение

Сохранён существующий том `dzencode-orders-products_mysql_data`. Пересборка образов не восстанавливает удалённые записи и не очищает базу. `docker compose stop` останавливает проект, `docker compose up -d --wait` запускает снова. `docker compose down` удаляет контейнеры и сеть, сохраняя том. Не используйте `down -v`, если данные нужны: эта команда удаляет том базы.

Compose читает корневой `.env`. Файлы `apps/api/.env` и `apps/web/.env.local` остаются для запуска вне Docker, в образы они не копируются. Контейнеры web/api работают от пользователя `node`, dev-зависимости API и исходники не нужны в runtime-образе. Next.js использует standalone-сборку.

Браузер обращается к `NEXT_PUBLIC_API_URL=http://localhost:4000`, SSR внутри сети Docker — к `http://api:4000`, API к `db:3306`. Используйте один hostname для сайта и API, чтобы передавалась cookie сессии. `NEXT_PUBLIC_API_URL` встраивается при сборке: после изменения адреса нужна пересборка web. Если меняете порты, обновите `WEB_PORT`, `API_PORT`, `CLIENT_ORIGIN` и `NEXT_PUBLIC_API_URL` согласованно.

Конфигурация предназначена для локального HTTP и публикует порты только на 127.0.0.1. `COOKIE_SECURE=false` позволяет вход по HTTP; для развёртывания с HTTPS установите `COOKIE_SECURE=true`, задайте реальные адреса и отдельные секреты. Без явной настройки API использует Secure cookie в production.

## Проверка и диагностика

Проверьте вход, оба списка, фильтр, язык, диаграмму, карту и открытие окна удаления. Для проверки удаления используйте запись, которую готовы удалить: операция меняет постоянную базу. Откройте две вкладки и проверьте счётчик. В исходном HTML `/orders` после входа должны быть названия приходов (SSR).

```bash
docker compose logs --tail=100 api web
docker compose ps
docker compose stop
```

Если порт занят, остановите соответствующий локальный сервер. Если API сообщает об ошибке доступа к MySQL, проверьте пароль: изменение `.env` не меняет пароль в уже созданном томе. Интернет нужен для первой сборки, а также для изображений карты OpenStreetMap.
