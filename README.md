# Orders & Products

Тестовое задание DZencode на позицию Junior+ React Developer: приложение учёта приходов и товаров.

## Статус проекта

Создана основа интерфейса на Next.js и TypeScript в `apps/web`. Подключены Bootstrap и SCSS, добавлены верхняя панель и боковое меню. На `/orders` отображаются четыре демонстрационных прихода: название, количество связанных товаров, дата в двух форматах и суммы USD/UAH. На `/products` отображается список товаров с фильтром по типу и счётчиком найденных позиций. Обе страницы доступны через меню; `/` перенаправляет на `/orders`. Активный раздел выделяется, при переходе используется анимация появления с учётом настройки уменьшения движения.

В списке продуктов показаны название, серийный номер, тип, начало и окончание гарантии в двух форматах, состояние, цены и связанный приход. Данные берутся из общего Redux-состояния: удаление прихода отражается и на странице продуктов. Для пустого списка предусмотрено сообщение, на узких экранах таблицу можно прокручивать по горизонтали.

По нажатию на название прихода открывается панель связанных товаров, а список становится компактнее. Панель закрывается крестиком или клавишей Escape при фокусе внутри неё. Для пустого прихода выводится отдельное сообщение. На узких экранах панель располагается под списком.

Подключены Redux Toolkit и React Redux. Корзина в строке прихода открывает окно подтверждения с названием и предупреждением об удалении связанных товаров. Подтверждение отправляет `DELETE /orders/:id`: MySQL каскадно удаляет приход, товары и цены. После успеха обновляются кэш обоих списков и счётчик, закрывается панель удалённого прихода. Во время запроса кнопки заблокированы и закрытие окна отключено; при ошибке окно остаётся открытым с возможностью повторить запрос. До отправки запроса отмена, крестик и Escape сохраняют данные. Удаление сохраняется после перезагрузки страницы.

Верхняя панель показывает текущую дату, день недели и время устройства в формате ЧЧ:ММ. Часы обновляются автоматически, в том числе после возвращения к вкладке. Поиск пока не подключён к данным. Разделы «Группы», «Пользователи» и «Настройки» отображаются без переходов.

В `apps/api` добавлена основа сервера Express на TypeScript с маршрутом `GET /health`. К этому же HTTP-серверу подключён Socket.io: в хедере отображается число активных подключённых вкладок. При потере соединения показывается прочерк, после восстановления клиент подключается автоматически. Списки приходов и товаров загружаются из API через RTK Query. Добавлены загрузка, сообщение об ошибке и кнопка повторного запроса; при ошибке локальные демонстрационные данные не подставляются. Добавлена локальная MySQL через Docker Compose с постоянным томом и начальными данными. API подключён к MySQL через mysql2: `GET /orders` и `GET /products` возвращают данные БД, `GET /health/db` проверяет соединение. RTK Query хранит ответы API в Redux-кэше, общем для обеих страниц. Добавлены вход с JWT, форма с валидацией и выход. API данных защищён сессией в HttpOnly-cookie; интеграционный тест авторизации запускается через `npm run test:auth`. Контейнеризация интерфейса и API ещё не добавлена.

Описанный ниже функционал — план реализации. Таблица технологий включает как подключённые инструменты, так и запланированные.

## Планируемый функционал

- Страницы «Приходы» и «Продукты» с навигацией и анимациями переходов.
- Список приходов: название, количество товаров, дата в двух форматах и суммы отдельно в USD и UAH.
- Просмотр товаров выбранного прихода в боковой панели.
- Удаление прихода с подтверждением.
- Список товаров с фильтром по типу, сроками гарантии, ценами и названием связанного прихода.
- Отображение текущих даты и времени.
- Счётчик активных подключений приложения через Socket.io.
- Формы с проверкой введённых данных.

## Запуск и проверка

Требуются Node.js 24.x и npm 11.x. Все команды выполняются из корня репозитория.

Установка зависимостей по файлу `package-lock.json`:

```sh
npm ci
```

Запуск в режиме разработки:

```sh
npm run dev
```

Откройте http://localhost:3000. Если порт занят, сервер разработки сообщит другой адрес в терминале. Для остановки нажмите `Ctrl+C`.

Проверка типов:

```sh
npm run typecheck
```

Сборка и запуск собранного приложения:

```sh
npm run build
npm run start
```

### Сервер API

Перед первым запуском настройте [авторизацию и демо-пользователя](docs/authentication.md): нужны `JWT_SECRET`, `DEMO_EMAIL`, `DEMO_PASSWORD` и команда `npm run setup:auth`. После включения авторизации маршруты данных возвращают 401 без входа. Откройте `/login` в интерфейсе, затем проверяйте данные. Перед первым запуском API скопируйте `apps/api/.env.example` в `apps/api/.env`. Значения `DB_PORT` и `DB_PASSWORD` должны совпадать с корневым `.env` для Compose. Запустите базу через `npm run db:up`. Затем в отдельном терминале из корня репозитория:

```sh
npm run dev:api
```

Откройте http://localhost:4000/health. Ожидаемый ответ:

```json
{"status":"ok","service":"orders-products-api"}
```

Сервер автоматически перезапускается после изменения исходников. Для остановки нажмите `Ctrl+C`. Неизвестные маршруты возвращают HTTP 404; страница `/` у API не предусмотрена.

По умолчанию используется порт 4000. Чтобы изменить его, скопируйте `apps/api/.env.example` в `apps/api/.env`, задайте `PORT` и перезапустите сервер. Node.js читает этот файл при запуске; переменные окружения процесса имеют приоритет.

Проверка типов, сборка и запуск собранного API:

```sh
npm run typecheck:api
npm run build:api
npm run start:api
```

Команды `dev`, `build`, `start`, `typecheck` относятся к веб-приложению; варианты с `:api` — к серверу. Для локальной MySQL добавлены `npm run db:up`, `npm run db:stop`, `npm run db:status` и `npm run db:logs`. Перед первым запуском БД скопируйте корневой `.env.example` в `.env`. [Подробная инструкция запуска и проверки MySQL](database/local-development.md). Для маршрутов данных API нужна работающая MySQL. `/health` проверяет только HTTP-сервер, а `/health/db` — подключение к БД.

### Проверка счётчика вкладок

Запустите `npm run dev:api` и `npm run dev` в двух терминалах. Откройте http://localhost:3000 в двух вкладках: обе должны показать одинаковое число активных подключений. Закройте одну вкладку — число уменьшится. Переходы между приходами и продуктами не создают дополнительных соединений.

Остановите API: счётчик сменится на прочерк. После повторного запуска API вкладки автоматически переподключатся. При обрыве сети отключение может определяться с задержкой до истечения тайм-аута соединения. Считаются все подключённые вкладки, включая фоновые, а не уникальные пользователи. Реализация рассчитана на один процесс API.

Для других адресов задайте `CLIENT_ORIGIN` в `apps/api/.env` (адрес интерфейса, по умолчанию `http://localhost:3000`) и `NEXT_PUBLIC_API_URL` в `apps/web/.env.local` (адрес API, по умолчанию `http://localhost:4000`). Примеры находятся в `.env.example` каждого приложения. После изменения переменных перезапустите соответствующие процессы; для production значение `NEXT_PUBLIC_API_URL` задаётся до сборки Next.js.

```text

  package.json       # Зависимости и команды интерфейса

  src/
    app.ts          # Express-приложение и GET /health
```

Локальные `.env`-файлы исключены из Git. Файлы примеров окружения должны содержать только демонстрационные значения без действующих секретов.

## Стили

В корневом `layout.tsx` сначала подключается готовый CSS Bootstrap, затем собственный `globals.scss`. Bootstrap используется для сетки, отступов и базового оформления; собственные классы именуются по БЭМ, например `navigation-menu__item`.

SCSS компилируется Next.js с помощью пакета `sass`. Отдельная команда компиляции стилей не требуется. Сетка и отступы заданы Bootstrap, а фон, оформление меню и анимация страниц — собственными SCSS-стилями.

JavaScript-плагины Bootstrap не подключены. Поведение интерактивных компонентов будет реализовано средствами React.

## Данные и схема БД

Основная связь: один приход содержит несколько товаров, каждый товар относится к своему приходу. Цены в USD и UAH учитываются отдельно.

Текущие демонстрационные данные находятся в `apps/web/src/data/inventory.ts`, типы — в `apps/web/src/types/inventory.ts`. Товар связан с приходом через `orderId`. Денежные значения `amountMinor` хранятся целыми числами в центах/копейках; суммы вычисляются отдельно для каждой валюты, без конвертации. Приход без товаров показывает нулевое количество и нулевые суммы. Для отображения дат используется часовой пояс `Europe/Kyiv`.

Подготовлен SQL-источник схемы: [database/schema.sql](database/schema.sql). Шесть таблиц: приходы, типы товаров, товары, цены, пользователи и сессии авторизации. Удаление прихода каскадно удаляет связанные товары и цены. [Описание схемы и импорт в MySQL Workbench](database/README.md) содержат правила хранения и соответствие полям React. Создание таблиц, ограничения и каскадное удаление проверены на MySQL 8.4.11. Импорт в Workbench пока не проверен; файл модели `.mwb` и миграции будут подготовлены на следующих этапах. Демонстрационные данные находятся в [database/seed.sql](database/seed.sql) и загружаются Compose при первом запуске на пустом томе.
